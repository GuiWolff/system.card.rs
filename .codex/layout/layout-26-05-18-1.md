## Regras gerais
- Executar apenas um slice por vez.
- Nunca executar slices em paralelo.
- Nunca avançar para o próximo slice sem o resumo do slice atual.
- Se um resumo de slice já existir e estiver válido, não repetir esse slice.
- Cada slice deve considerar o estado atualizado do código produzido pelo slice anterior.
- Cada slice que alterar UI deve atualizar `lib/features/pedido_page/presentation/pages/pedido_page-contrato.md`.
- Cada slice deve ler as regras e skills aplicáveis antes de alterar código.
- Cada slice deve rodar validações conforme a skill aplicável.
- Preservar alterações existentes no worktree.
- Não fazer commit automaticamente.
- Não criar nova `Page`, rota ou feature paralela para substituir a `PedidoPage`.
- Não alterar APIs públicas sem necessidade.
- Não remover código legado, assets SVG, `font_awesome_flutter`, `flutter_svg` ou dependências sem confirmação explícita ou justificativa técnica dentro do escopo.
- Não alterar services de PDF, impressão, compartilhamento, repositories, DTOs ou schema SQLite quando o slice for apenas visual.
- Não usar `FaIcon` para ícones que não sejam WhatsApp ou Instagram.
- Não adicionar pacote `fluent_ui`; a direção Microsoft deve ser aplicada com Flutter Material 3 e padrões locais.
